# Atari DQN fidelity review

This review compares the single-player Atari implementation at `08d531c` with Mnih et al.’s 2015 Nature paper, *Human-level control through deep reinforcement learning*, and DeepMind’s released Lua/Torch implementation. The repo matches the core DQN algorithm and the network architecture described in the paper. Its optimizer, training budgets, emulator behavior, and evaluation protocol differ. The paper and the released code also use different units for the target-network sync interval. [Nature paper](https://doi.org/10.1038/nature14236) · [Full paper and extended data](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf) · [DeepMind release](https://github.com/google-deepmind/dqn)

## What matches

| Area | Shared behavior |
| --- | --- |
| **Network architecture** | Four `84 × 84` grayscale frames feed three ReLU convolutional layers. The layers have 32 filters of `8 × 8` at stride 4, 64 of `4 × 4` at stride 2, and 64 of `3 × 3` at stride 1. A 512-unit ReLU layer feeds a linear output with one Q-value per available action. [Repo model](../src/model.py#L20-L33) · [Paper, Model architecture](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf#page=6) |
| **Bellman target** | Vanilla one-step Q-learning uses the reward plus `0.99 × max Q_target(next_state)` for a nonterminal transition. Terminal transitions use the reward alone. The learner updates the online network and periodically copies its weights to the target network. [Repo agent](../src/agent.py#L136-L201) · [Paper, Algorithm 1](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf) |
| **Replay and update cadence** | Both keep recent experience in a circular buffer, sample uniformly from eligible experience, and use batches of 32. After warm-up, each takes one optimizer step per four agent steps. Both start with uniformly random actions during warm-up and use an ε-greedy training policy. [Repo training loop](../train.py#L276-L307) · [DeepMind launcher](https://github.com/google-deepmind/dqn/blob/master/run_gpu) |
| **Observation pipeline** | Both use a nominal action repeat of four emulator frames. Both max-pool two RGB frames to reduce sprite flicker, convert to a single luminance-like channel, resize the image, and stack four observations. Both use randomized no-op starts with a maximum setting of 30. [Repo wrappers](../src/wrappers.py#L210-L240) · [Paper, Preprocessing and Extended Data Table 1](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf) |
| **Rewards and life loss** | Training clips reward magnitudes to one. Losing a life cuts off the training bootstrap in games with a life counter. Evaluation uses the raw score and continues across lives. [Repo reward and life handling](../src/wrappers.py#L98-L151) · [Repo evaluation](../evaluate.py#L31-L41) · [Paper, Training details and Evaluation procedure](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf#page=6) |

## Learning and replay differences

| Area | Current repo | Nature paper or DeepMind release |
| --- | --- | --- |
| **Optimizer and gradients** | Adam at `1e-4`, Smooth L1 loss, and global gradient-norm clipping at `10`. Smooth L1 produces the same per-sample clipping shape as the original TD-error update before batch reduction and global clipping. | RMSProp at `2.5e-4`. The released learner tracks the first and second moments with a decay of `0.95`, centers the second moment, and adds `0.01` inside the square root. It clips each TD error to `[-1, 1]`. [Repo optimizer](../src/agent.py#L85-L89) · [Repo gradient step](../src/agent.py#L188-L196) · [DeepMind update](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L209-L258) |
| **Replay capacity and warm-up** | 100,000 transitions with learning starting at 10,000 stored transitions. | The released launcher uses 1 million replay entries and 50,000 warm-up steps. [Repo defaults](../train.py#L57-L69) · [DeepMind launcher](https://github.com/google-deepmind/dqn/blob/master/run_gpu) |
| **Replay storage and sampling** | Each transition stores the full current and next four-frame stacks. The two observation arrays take about 5.6 GB at 100,000 entries. Each update samples directly from the buffer with replacement. | The release stores one byte frame per entry, reconstructs the stacks from adjacent entries, and prefetches eligible samples in blocks of 512. Its samples must have enough history and a nonterminal current state. [Repo replay](../src/replay_buffer.py#L40-L92) · [DeepMind replay](https://github.com/google-deepmind/dqn/blob/master/dqn/TransitionTable.lua) |
| **Exploration** | ε falls from `1.0` to `0.02` over 1 million agent steps. The decay counter runs during warm-up, while warm-up actions remain uniformly random. Greedy `argmax` takes the first maximum in a tie. | The paper gives a final ε of `0.1`. The Lua learner keeps ε at `1.0` through warm-up, then decays over 1 million steps. It breaks greedy ties randomly. [Repo action selection](../src/agent.py#L94-L137) · [DeepMind exploration](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L342-L383) |
| **Target-network interval** | Every **1,000 optimizer updates**, about **4,000 agent steps** at the default cadence. | Extended Data Table 1 specifies **10,000 parameter updates**. The released learner applies the interval to its environment-step counter, giving **10,000 steps**, or roughly **2,500 optimizer updates** at the default cadence. [Repo target sync](../src/agent.py#L195-L201) · [Paper, Extended Data Table 1](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf) · [DeepMind target sync](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L316-L333) |
| **Training budget and frame accounting** | The CLI defaults to **1.5 million agent steps**, nominally **6 million emulator frames**. The documented Pong run reached **10 million agent steps**, nominally **40 million emulator frames**. | The paper says **50 million frames**. The released launcher sets **50 million training-loop steps**, and the logger multiplies that counter by four for a nominal **200 million emulator frames**. Reset actions and early termination affect actual frame counts. [Repo CLI](../train.py#L26-L31) · [Repo Pong run](../README.md#experimental-results-telemetry--empirical-findings) · [DeepMind launcher](https://github.com/google-deepmind/dqn/blob/master/run_gpu) · [DeepMind frame accounting](https://github.com/google-deepmind/dqn/blob/master/dqn/train_agent.lua#L149-L157) |
| **DQN variant** | Vanilla DQN is the default. The optional Double DQN mode chooses the next action with the online network and evaluates it with the target network. | Nature DQN uses the maximum over the target network’s next-state Q-values. [Repo target calculation](../src/agent.py#L165-L186) · [DeepMind target calculation](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L167-L207) |

## Emulator and observation differences

| Area | Current repo | Nature paper or DeepMind release |
| --- | --- | --- |
| **Emulator and sticky actions** | Gymnasium and modern ALE v5. The sticky-action probability is 25%, so the emulator can execute the previous action even when the agent requests a different one. | The release uses Xitari through AleWrap. It predates sticky actions. Both share deliberate four-frame action repeat. [Repo environment construction](../src/wrappers.py#L210-L225) · [ALE environment settings](https://ale.farama.org/environments/) · [DeepMind dependencies](https://github.com/google-deepmind/dqn#installation-instructions) |
| **Color conversion and resizing** | OpenCV RGB-to-grayscale conversion and area interpolation. | The released preprocessing uses Torch’s RGB-to-Y conversion and bilinear resizing. [Repo image processing](../src/wrappers.py#L105-L119) · [DeepMind scaler](https://github.com/google-deepmind/dqn/blob/master/dqn/Scale.lua) |
| **Frame history across resets** | The first observation fills all four slots after a reset, including the reset triggered by a lost life during training. | The released replay code zeros history before an episode boundary and copies the frames available in the current episode. [Repo frame stacking](../src/wrappers.py#L183-L207) · [DeepMind frame stacking](https://github.com/google-deepmind/dqn/blob/master/dqn/TransitionTable.lua#L161-L198) |
| **Initialization and padding** | The model uses Kaiming-normal initialization, zero biases, and unpadded convolutions. | The Lua builder uses Torch’s layer initialization. Its CPU path passes one pixel of padding to the first convolution. The paper specifies the filter sizes, channel counts, and strides. [Repo model](../src/model.py#L25-L47) · [DeepMind builder](https://github.com/google-deepmind/dqn/blob/master/dqn/convnet.lua#L13-L29) · [Torch convolution signature](https://github.com/torch/nn/blob/master/SpatialConvolution.lua#L3-L17) |
| **Automatic game actions** | Reset can send FIRE followed by action index 2. The evaluation wrapper can send an additional FIRE after life loss, including in Breakout. | The published evaluation starts from randomized no-op conditions. The released evaluation loop passes the action selected by the policy to the emulator. [Repo reset wrapper](../src/wrappers.py#L46-L62) · [Repo life-loss wrapper](../src/wrappers.py#L155-L175) · [DeepMind evaluation](https://github.com/google-deepmind/dqn/blob/master/dqn/train_agent.lua#L98-L125) |
| **Time-limit handling during training** | Gymnasium truncation ends the rollout and resets the environment. The replay terminal flag uses `terminated`, so a transition with truncation alone can still bootstrap. | The released learner accepts a single terminal flag and masks the bootstrap with it. [Repo rollout and replay](../train.py#L284-L307) · [DeepMind target calculation](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L167-L193) |

## Evaluation and reporting differences

| Area | Current repo | Nature paper or DeepMind release |
| --- | --- | --- |
| **Standalone evaluation** | Defaults to 10 episodes and greedy action selection. `--epsilon` can enable exploratory actions. Episodes end at game over or the ALE limit. | The published benchmark ran 30 episodes per game, capped at five minutes each, with randomized no-op starts and `ε = 0.05`. Five minutes is 18,000 emulator frames at 60 Hz. [Repo evaluator](../evaluate.py#L18-L26) · [Evaluation loop](../evaluate.py#L60-L79) · [Paper, Evaluation procedure](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf#page=6) |
| **Checkpoint selection** | Periodic evaluation defaults to five greedy episodes every 25,000 agent steps in a separate environment. Best mean score determines `best_model.pt`. Optional score and patience settings allow early stopping. | The Lua launcher runs 125,000 evaluation steps every 250,000 training steps with `ε = 0.05`. It also retains the best model by mean score. This periodic evaluation serves a different purpose from the paper’s final 30-episode benchmark. [Repo training evaluation](../train.py#L337-L382) · [DeepMind launcher](https://github.com/google-deepmind/dqn/blob/master/run_gpu) · [DeepMind model selection](https://github.com/google-deepmind/dqn/blob/master/dqn/train_agent.lua#L98-L145) |
| **Learning diagnostics** | Running Q and loss metrics use training batches. The evaluation CSV records raw mean score, standard deviation, range, and mean episode length. | The Lua code also tracks average Q and TD-error statistics on a fixed sample drawn from replay after warm-up. [Repo metrics](../train.py#L304-L350) · [DeepMind validation statistics](https://github.com/google-deepmind/dqn/blob/master/dqn/NeuralQLearner.lua#L261-L275) |
| **Benchmark coverage** | The committed single-player training and evaluation logs cover Pong and Breakout. | The paper trains a separate model for each of 49 Atari games with common settings. It reports raw scores, comparisons with prior methods, and human-normalized scores anchored to a random policy and a professional human tester. [Repo results](../README.md#directory-structure) · [Paper, Extended Data Table 2](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf) |

## Interpreting the reported scores

| Game | Peak mean in committed repo logs | Published Nature DQN mean ± standard deviation |
| --- | ---: | ---: |
| Pong | +20.4 at 5.1 million agent steps. [Repo metrics](../checkpoints/eval_metrics.csv) | +18.9 ± 1.3 |
| Breakout | 12.4 at 500,000 agent steps. [Repo metrics](../checkpoints_breakout/eval_metrics.csv) | 401.2 ± 26.9 |

These are results from different training budgets and evaluation protocols. The repo logs show learning under its setup. The paper scores describe a benchmark with its own emulator, evaluation cap, exploration rate, and baselines. In particular, adding `--epsilon 0.05` changes the current policy’s random-action probability. A score comparison also depends on episode count, cap, sticky actions, and automatic FIRE. [Paper, Evaluation procedure and Extended Data Table 2](https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf)

## Reproduction work still open

- **Benchmark consistency.** The training evaluator derives seeds from the checkpoint step. Scores can therefore vary with the sampled starts as well as policy quality. A fixed evaluation seed set and separate final evaluation would make checkpoint comparisons easier to interpret. [Evaluation call](../train.py#L337-L339)
- **Replay scaling.** With the current layout, the paper-sized buffer would require about 56.4 GB for the two observation arrays alone. Storing single frames and reconstructing stacks across episode boundaries would reduce that cost. Replacing `latest.pt` retires its previous versioned replay snapshot, while distinct periodic checkpoint files and their replay snapshots accumulate. [Replay layout](../src/replay_buffer.py#L40-L51) · [Checkpoint publication](../src/agent.py#L213-L252) · [Periodic checkpoints](../train.py#L384-L388)
